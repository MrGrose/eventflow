# Эксплуатационная готовность и ограничения

## Реализованные механизмы надёжности

- **Атомарность записи и доставка:** паттерн Transactional Outbox в PostgreSQL с конкурентной выборкой `FOR UPDATE SKIP LOCKED`, арендой строк (`lease_expires_at`), автоматическим возвратом зависших записей (`recover_stale_leases`) и экспоненциальным backoff.
- **Гарантии обработки:** доставка `at-least-once` в сочетании с идемпотентными транзакциями консьюмеров через таблицу `processed_events` и блокировкой складских остатков `SELECT ... FOR UPDATE`.
- **Разделение ошибок:** временные сбои (`RetryableProcessingError`, сетевые ошибки) возвращаются на повторную обработку, а постоянные ошибки (`PermanentProcessingError`) маршрутизируются в `eventflow.dlq.{consumer}` (RabbitMQ) или `eventflow.events.dlt` (Kafka) без бесконечного цикла повторов.
- **Наблюдаемость:** структурированные JSON-логи в `stdout`, проброс `X-Correlation-ID`, проверка готовности БД и активного брокера на `GET /ready`, экспорт метрик Prometheus на `GET /metrics` и готовый дашборд Grafana (`observability/grafana/dashboards/eventflow.json`).
- **Автоматическая проверка в CI:** пайплайн `.github/workflows/ci.yml` проверяет линтинг, форматирование, модульные тесты и интеграционные прогоны для RabbitMQ и Kafka с предварительным накатом миграций `alembic upgrade head`.

## Операционные регламенты

- Накат миграций перед стартом API и воркеров: `uv run alembic upgrade head`.
- Мониторинг и проверка при отказах: [observability-runbook.md](observability-runbook.md).
- Разбор сообщений в DLQ и DLT: [dlq-dlt-playbook.md](dlq-dlt-playbook.md).
- Запуск сравнительных сценариев E1–E9: `make lab` (результаты сохраняются в `docs/lab/results/`).

## Известные ограничения текущей конфигурации

При развёртывании за пределами локальной среды разработки необходимо учитывать следующие ограничения:

| Область | Текущее состояние (dev) | Что требуется для защищённого контура |
|---------|-------------------------|---------------------------------------|
| Шифрование трафика брокеров | Используются нешифрованные соединения (`AMQP` и Kafka `PLAINTEXT`) | Включение TLS для RabbitMQ и TLS/SASL для Kafka |
| Учётные данные в Compose | В `docker-compose.yml` и `.env.example` заданы стандартные локальные пароли (`eventflow`, `guest`, `admin`) | Передача секретов через внешний Secret Manager / Vault и отключение публичных портов БД и брокеров |
| Аутентификация HTTP API | Эндпоинты `/orders` и `/metrics` открыты без авторизации | Размещение за API Gateway (JWT / mTLS) и изоляция сети для сбора `/metrics` |
| Сбор метрик с воркеров | Эндпоинт `/metrics` отдаёт метрики процесса API | При запуске воркеров в отдельных контейнерах — добавление HTTP-экспортера метрик в процесс воркера |
