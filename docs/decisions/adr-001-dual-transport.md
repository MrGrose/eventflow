# ADR-001: Два независимых транспорта (RabbitMQ и Kafka)

**Статус:** Accepted

## Контекст

Система поддерживает доставку доменных событий через брокер очередей (RabbitMQ) и через распределённый лог (Apache Kafka). Необходимо сохранить нативную семантику каждого брокера (подтверждения, партиционирование, управление смещениями, обработка сбоев) без размывания их особенностей за общей абстракцией.

## Решение

- Две отдельные реализации в `infrastructure/messaging/rabbitmq/` и `infrastructure/messaging/kafka/`.
- Общие элементы: доменная модель, схема `outbox_events`, конверт `EventEnvelope`, таблица дедупликации `processed_events` и метрики Prometheus с лейблом `transport=rabbitmq|kafka`.
- **Один активный транспорт** на окружение (`MESSAGING_TRANSPORT`).
- `outbox-publisher` и consumer-воркеры запускаются для выбранного транспорта.

## Альтернативы

| Вариант | Причина отказа |
|---------|----------------|
| Единая обёртка `BrokerClient` поверх обоих брокеров | Скрывает различия между AMQP ACK/DLX и партиционированным логом с коммитом смещений |
| Одновременная публикация каждого события в оба брокера | Усложняет координацию статусов outbox и приводит к двойной обработке |
| Поддержка только одного брокера | Не позволяет сопоставить queue-based и log-based подходы на одной доменной модели |

## Последствия

- Настройка топологии, retry и DLQ/DLT реализована отдельно для каждого транспорта.
- Сравнительные замеры выполняются последовательными прогонами на изолированном состоянии.
